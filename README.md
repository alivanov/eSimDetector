# eSIM Detector

Сервис определения устройства пользователя и статуса поддержки технологии eSIM. Определяет платформу и модель устройства по сигналам браузера (User-Agent, User-Agent Client Hints, характеристики экрана) либо по текстовому запросу пользователя, и выдаёт один из трёх статусов: `supported`, `not_supported`, `clarification_required`. Каждый ответ сопровождается машиночитаемым объяснением сработавших правил.

Ключевой принцип решения — приоритет точности над полнотой: при недостатке данных сервис честно возвращает `clarification_required`, а не строит догадку. Подробности архитектуры, алгоритмов и предметных ограничений — в [docs/README.md](./docs/README.md), начиная с [docs/02-architecture.md](./docs/02-architecture.md).

## Требования к окружению

- **Node.js 22+**
- **pnpm** (версия закреплена в `package.json` → `packageManager`; при наличии Corepack (`corepack enable`) нужная версия pnpm подтянется автоматически)
- **Docker** и **Docker Compose** — только для запуска демонстрационного контура (`docker compose up`). Для разработки, линтинга, проверки типов и модульных/e2e-тестов Docker не требуется: тесты поднимают собственный изолированный экземпляр MongoDB в памяти процесса (`mongodb-memory-server`).

## Установка

```bash
pnpm install
```

Первый запуск `pnpm test` скачивает бинарный файл MongoDB для `mongodb-memory-server` (кэшируется в `~/.cache/mongodb-binaries` либо в `node_modules/.cache/mongodb-memory-server`, если домашний каталог недоступен для записи) — для этого нужна сетевая связность; повторные запуски используют кэш.

## Команды

Выполняются из корня репозитория и применяются рекурсивно ко всем пакетам рабочего пространства (pnpm workspaces).

| Команда                             | Назначение                                                                                                                                                                     |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `pnpm dev`                          | Запуск всех приложений в режиме разработки параллельно (API, веб-приложение, виджет — по мере готовности)                                                                      |
| `pnpm build`                        | Сборка всех пакетов и приложений                                                                                                                                               |
| `pnpm lint`                         | Проверка стиля кода ESLint по всему репозиторию                                                                                                                                |
| `pnpm lint:fix`                     | Автоисправление того, что чинится автоматически                                                                                                                                |
| `pnpm format` / `pnpm format:check` | Форматирование Prettier / проверка форматирования без изменений                                                                                                                |
| `pnpm typecheck`                    | Проверка типов TypeScript во всех пакетах (`tsc --noEmit`)                                                                                                                     |
| `pnpm test`                         | Модульные и e2e-тесты. Не требует Docker, запущенной MongoDB и файла переменных окружения — см. [docs/08-testing-and-quality.md](./docs/08-testing-and-quality.md), раздел 8.5 |
| `docker compose up -d`              | Поднимает демонстрационный контур: MongoDB и API. После старта `curl http://localhost:3000/health/live` отвечает `{"status":"ok"}`                                             |
| `docker compose down`               | Останавливает и удаляет контейнеры демонстрационного контура                                                                                                                   |

Переменные окружения API, их назначение и значения по умолчанию — в [`.env.example`](./.env.example) и [docs/07-integration.md](./docs/07-integration.md), раздел 7.8. Копировать файл в `.env` не обязательно: значения по умолчанию рабочие, а тесты переменные окружения не используют вовсе.

## Структура репозитория

Монорепозиторий на pnpm workspaces (обоснование — [ADR-001](./docs/09-decisions.md)).

```
apps/
  api/      — REST API (NestJS + Mongoose)
  web/      — демонстрационное веб-приложение (React + Vite)
  widget/   — встраиваемый виджет одним тегом <script>
packages/
  contracts/          — общие типы запросов/ответов API и схемы валидации
  text-normalizer/    — нормализация пользовательского ввода
  fuzzy-matcher/      — нечёткое сопоставление и ранжирование кандидатов
  esim-rules/         — правила вывода статуса поддержки eSIM
  signals-collector/  — сбор сигналов устройства в браузере
  test-utils/         — изолированная тестовая база данных и защитные проверки
tools/
  seed/     — импорт и наполнение справочника устройств в MongoDB
  eval/     — стенд оценки качества автоопределения и обработки ввода
data/
  catalog/    — источник истины справочника устройств (версионируемые файлы, ADR-006)
  fixtures/   — эталонные выборки для тестов и стенда оценки качества
docs/         — документация проекта (архитектура, алгоритмы, ADR, контракт API)
```

Алгоритмическая часть (`text-normalizer`, `fuzzy-matcher`, `esim-rules`, `signals-collector`) не зависит от NestJS, HTTP и MongoDB и тестируется без поднятия приложения.

### `packages/test-utils` — изолированная тестовая база данных

| Пакет                   | Назначение                                                                                       |
| ----------------------- | ------------------------------------------------------------------------------------------------ |
| `mongodb-memory-server` | Поднимает настоящий сервер MongoDB в памяти для тестов, без Docker и внешней установки (ADR-017) |
| `mongoose`              | Подключение к поднятому тестовому серверу и защитные проверки перед разрушающими операциями      |

Пакеты `contracts`, `text-normalizer`, `fuzzy-matcher`, `esim-rules`, `signals-collector`, `tools/seed`, `tools/eval` на этапе фундамента ещё не имеют собственных runtime-зависимостей: их бизнес-логика реализуется на следующих этапах цепочки агентов (см. [docs/11-implementation-plan.md](./docs/11-implementation-plan.md)).
