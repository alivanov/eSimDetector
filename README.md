# eSIM Detector

Сервис определения устройства пользователя и статуса поддержки технологии eSIM. Определяет платформу и модель устройства по сигналам браузера (User-Agent, User-Agent Client Hints, характеристики экрана) либо по текстовому запросу пользователя, и выдаёт один из трёх статусов: `supported`, `not_supported`, `clarification_required`. Каждый ответ сопровождается машиночитаемым объяснением сработавших правил.

Ключевой принцип решения — приоритет точности над полнотой: при недостатке данных сервис честно возвращает `clarification_required`, а не строит догадку. Подробности архитектуры, алгоритмов и предметных ограничений — в [docs/README.md](./docs/README.md), начиная с [docs/02-architecture.md](./docs/02-architecture.md).

## Требования к окружению

- **Node.js 24+**
- **pnpm** (версия закреплена в `package.json` → `packageManager`; при наличии Corepack (`corepack enable`) нужная версия pnpm подтянется автоматически)
- **Docker** и **Docker Compose** — только для запуска демонстрационного контура (`docker compose up`). Для разработки, линтинга, проверки типов и модульных/e2e-тестов Docker не требуется: тесты поднимают собственный изолированный экземпляр MongoDB в памяти процесса (`mongodb-memory-server`).

## Установка

```bash
pnpm install
```

Первый запуск `pnpm test` скачивает бинарный файл MongoDB для `mongodb-memory-server` (кэшируется в `~/.cache/mongodb-binaries` либо в `node_modules/.cache/mongodb-memory-server`, если домашний каталог недоступен для записи) — для этого нужна сетевая связность; повторные запуски используют кэш.

`pnpm install` также ставит git-хук `pre-commit` (husky) — он прогоняет Prettier и ESLint только по файлам, попавшим в коммит (`lint-staged`), и останавливает коммит при неисправимых ошибках. Это защита от повторяющегося падения шага «Форматирование (Prettier)» в CI: несогласованный со стилем файл просто не попадёт в коммит.

## Быстрый старт (локальный демонстрационный контур)

Из корня репозитория, после `pnpm install`:

```bash
docker compose up -d
MONGODB_URI=mongodb://localhost:27017/esim pnpm seed load
MONGODB_URI=mongodb://localhost:27017/esim pnpm seed rebuild-signatures
docker compose restart api
```

После этого `http://localhost:8080` — интерфейс, `http://localhost:3000/health/ready` — готовность API. Справочник сам при `docker compose up` не загружается (ADR-015). Подробности и таблица адресов — [docs/07-integration.md](./docs/07-integration.md) §7.6.

### Пересборка образов

```bash
docker compose build api && docker compose up -d api    # только API
docker compose build web && docker compose up -d web    # только веб (виджет входит в этот образ)
docker compose build && docker compose up -d            # оба образа
```

После пересборки API, если справочник уже в базе, повторный `seed` не нужен — достаточно `docker compose up -d api` (новый контейнер читает базу при старте). Если менялись файлы в `data/catalog/`, снова выполните обе команды `pnpm seed` и `docker compose restart api`.

### Тесты

```bash
pnpm test          # модульные и e2e API — без Docker, без MongoDB, без .env (ADR-017)
pnpm test:e2e      # e2e интерфейса в браузере; нужен уже поднятый контур
```

`pnpm test` специально **не** гоняется внутри контейнеров приложения: тесты поднимают свою MongoDB в памяти процесса (`mongodb-memory-server`) и не имеют права видеть базу демонстрационного контура. «Тесты в контейнерах» в этом проекте — это e2e против уже запущенного `docker compose`:

```bash
docker compose up -d
npx playwright install chromium    # один раз на машину
pnpm test:e2e
```

Сборка образов как проверка, что Docker-файлы не сломаны (то же делает CI):

```bash
docker compose build
```

| `docker compose down`               | Останавливает и удаляет контейнеры демонстрационного контура                                                                                                                                                                                                                                                                   |

## Публичный стенд

Помимо локального запуска, предусмотрен публичный стенд на Render (render.com) — [ADR-027](./docs/09-decisions.md) с дополнением: API и веб — два Web Service из тех же Docker-образов, что `docker compose`, база — MongoDB Atlas. Пошаговая инструкция первого деплоя и обновления (для человека без опыта DevOps) — [docs/16-deployment.md](./docs/16-deployment.md). Краткая топология — [docs/07-integration.md](./docs/07-integration.md) §7.6а. Публичные адреса `onrender.com` появятся в §7.6а и здесь после выкладки.

Captcha на демонстрационном стенде не подключается: достаточно `RATE_LIMIT_RPM`, `CORS_ORIGINS` и `ADMIN_TOKEN` (обоснование — docs/16 §16.3).

## Структура репозитория

Монорепозиторий на pnpm workspaces (обоснование — [ADR-001](./docs/09-decisions.md)).

```
apps/
  api/      — REST API (NestJS + Mongoose)
  web/      — демонстрационное веб-приложение (React + Vite)
  widget/   — встраиваемый виджет одним тегом <script>
  e2e/      — e2e-тесты интерфейса в настоящем браузере (Playwright, docs/08 §8.3)
packages/
  contracts/          — общие типы запросов/ответов API и схемы валидации
  text-normalizer/    — нормализация пользовательского ввода
  fuzzy-matcher/      — нечёткое сопоставление и ранжирование кандидатов
  esim-rules/         — правила вывода статуса поддержки eSIM
  signals-collector/  — сбор сигналов устройства в браузере
  ui-tokens/          — слой токенов дизайна (цвета, типографика, отступы, формы, состояния, компоненты)
  test-utils/         — изолированная тестовая база данных и защитные проверки
tools/
  seed/     — импорт и наполнение справочника устройств в MongoDB
  eval/     — стенд оценки качества автоопределения и обработки ввода
data/
  catalog/    — источник истины справочника устройств (версионируемые файлы, ADR-006)
  fixtures/   — эталонные выборки для тестов и стенда оценки качества
docs/         — документация проекта (архитектура, алгоритмы, ADR, контракт API)
```

Алгоритмическая часть (`text-normalizer`, `fuzzy-matcher`, `esim-rules`, `signals-collector`) не зависит от NestJS, HTTP и MongoDB и тестируется без поднятия приложения.
