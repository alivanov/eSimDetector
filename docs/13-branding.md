# 13. Брендбук СберМобайл и оформление интерфейса

## 13.1. Что даёт брендбук и чего он не даёт

ТЗ ссылается на брендбук СберМобайл в Figma:

```
https://www.figma.com/design/Q2lrTU85ohdbpBQIOe48KW/SberMobile_guide?node-id=1-8253
```

Формально критерии оценки не содержат пункта «соответствие фирменному стилю»: требование к интерфейсу — «понятный и однозначный результат», «отсутствие неоднозначных формулировок», «понятен без дополнительного обучения». Однако ссылка приведена в ТЗ намеренно, и решение, визуально узнаваемое как продукт СберМобайл, при демонстрации воспринимается как готовое к встраиванию, а не как прототип. Это косвенно поддерживает и критерий К4.

Поэтому подход такой: **интерфейс проектируется независимо от доступа к брендбуку, а фирменный стиль применяется как заменяемый слой.**

## 13.2. Слой токенов дизайна

Все визуальные значения выносятся в один файл токенов (`packages/ui-tokens`), из которого генерируются CSS-переменные:

| Группа токенов | Состав |
|---|---|
| Цвета | Основной, вторичный, фон, поверхность, текст (основной, вторичный, инверсный), границы, состояния (успех, предупреждение, ошибка, информация) |
| Типографика | Гарнитура, шкала кеглей, интерлиньяж, насыщенность, регистровые правила заголовков |
| Отступы | Шкала отступов и внутренних полей |
| Формы | Радиусы скругления, толщина границ, тени |
| Состояния | Наведение, нажатие, фокус, недоступность, загрузка |
| Компоненты | Кнопки (основная, вторичная, текстовая), поле ввода с подсказками, элемент списка выбора, карточка результата, индикатор загрузки |

Замена оформления на фирменное — правка значений в одном файле, без изменения разметки и логики. Это зафиксировано как ADR-012.

Для трёх статусов результата в брендбуке потребуются: цвет и иконка успеха (поддерживает), цвет и иконка отказа (не поддерживает), цвет и иконка нейтрального/информационного состояния (требуется уточнение). Важно, чтобы «не поддерживает» не выглядело как сообщение об ошибке приложения: это корректный результат, а не сбой.

## 13.3. Что нужно для работы с Figma

На данный момент в рабочем окружении настроены серверы MCP для Context7, Playwright и Prisma. Сервера MCP для Figma нет, поэтому прочитать брендбук в текущей конфигурации я не могу. Ниже — варианты по возрастанию требований.

### Вариант А. Токен доступа Figma REST API (рекомендуемый, без установки MCP)

Самый простой путь. Достаточно личного токена доступа Figma от учётной записи, которая может открыть файл по ссылке.

1. Figma → Settings → Security → Personal access tokens → создать токен со правами чтения содержимого файлов (`file_content:read`, дополнительно `file_dev_resources:read`).
2. Передать токен через переменную окружения (не в текст переписки и не в репозиторий):

```bash
export FIGMA_TOKEN="figd_..."
```

После этого я смогу получить структуру нужного узла брендбука, перечень стилей (цвета, текстовые стили) и выгрузить изображения фреймов:

```bash
# файл: Q2lrTU85ohdbpBQIOe48KW, узел из ссылки: 1-8253 → 1:8253
curl -s -H "X-Figma-Token: $FIGMA_TOKEN" \
  "https://api.figma.com/v1/files/Q2lrTU85ohdbpBQIOe48KW/nodes?ids=1:8253"
curl -s -H "X-Figma-Token: $FIGMA_TOKEN" \
  "https://api.figma.com/v1/files/Q2lrTU85ohdbpBQIOe48KW/styles"
```

Ограничение: токен даёт доступ только к тем файлам, которые доступны его владельцу. Если ссылка из ТЗ открывается у вас в браузере — токен подойдёт.

### Вариант Б. Сервер MCP для Figma

Даёт более удобную работу с макетами (получение кода компонента, скриншотов узлов, переменных дизайна).

- **Удалённый сервер Figma:** добавить в конфигурацию MCP адрес `https://mcp.figma.com/mcp`, авторизация через OAuth в браузере.
- **Локальный сервер в приложении Figma:** в настольном приложении Figma включить Dev Mode MCP Server, после чего сервер доступен по адресу `http://127.0.0.1:3845/mcp`.

Требования: учётная запись Figma с доступом к файлу; для инструментов режима разработчика нужен соответствующий тип места в тарифе Figma (Dev или Full на платном плане). Если такого места нет, вариант А остаётся работоспособным.

Готов подготовить фрагмент конфигурации MCP для добавления в проект, если выберете этот вариант.

### Вариант В. Выгрузка вручную

Если доступ к API и MCP получить не удаётся, достаточно любого из перечисленного:

- экспорт нужных фреймов брендбука в PNG или PDF (я прочитаю изображения и сниму с них значения);
- выгрузка переменных дизайна или стилей из Figma в JSON;
- просто перечень значений: основные цвета в HEX, названия гарнитур, шкала кеглей, радиусы скругления.

Практически этого достаточно: для нашего интерфейса нужны около двадцати значений, а не весь брендбук.

## 13.4. Требования к интерфейсу, не зависящие от брендбука

Эти требования выполняются независимо от доступа к фирменному стилю и напрямую влияют на оценку.

| Требование | Реализация |
|---|---|
| Однозначность результата | Ровно три состояния результата, единая формулировка для каждого, отсутствие промежуточных трактовок |
| Понятность без обучения | Один экран, один основной элемент действия, результат в заголовке, а не в подписи |
| Отсутствие неоднозначных формулировок | Тексты проверяются по контрольному списку: без слов «возможно», «вероятно», «скорее всего» в статусе результата |
| Уточнение не выглядит ошибкой | Нейтральное оформление, формулировка «нужно уточнить», а не «не удалось определить»; всегда предлагается следующий шаг |
| Только русский язык | Все тексты в ресурсах на русском языке; проверка отсутствия иноязычных строк в интерфейсе — автоматическая |
| Доступность | Работа с клавиатуры, разметка для экранного диктора, контраст не ниже AA, корректная работа при увеличенном системном шрифте |
| Соответствие каналу | Виджет не навязывает страницу-обёртку, наследует ширину контейнера, не блокирует прокрутку |

## 13.5. Формулировки для трёх статусов `[черновик]`

Тексты приведены в ответе API в блоке `presentation`, чтобы заказчик получал согласованные формулировки даже при использовании только API.

| Статус | Заголовок | Пояснение | Действие |
|---|---|---|---|
| `supported` | «Ваше устройство поддерживает eSIM» | Название или группа моделей, при наличии — упоминание совместной работы с физической SIM | «Подключить eSIM» |
| `not_supported` | «Ваше устройство не поддерживает eSIM» | Указание модели и предложение доступной альтернативы | «Подобрать SIM-карту» |
| `clarification_required` | «Нужно уточнить модель устройства» | Причина в одну строку, без технических терминов | «Выбрать модель» / «Указать вручную» |

Формулировки подлежат согласованию с командой: они видны пользователю и оцениваются комиссией напрямую.
