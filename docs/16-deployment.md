# 16. Публикация демонстрационного стенда

Пошаговая инструкция для человека, который никогда ничего не выкладывал в интернет. Сам деплой выполняется руками в панелях MongoDB Atlas и Render; этот документ — что нажимать и в каком порядке.

Локальный запуск через Docker Compose не отменяется: он по-прежнему основной путь разработки и проверки ([07-integration.md](./07-integration.md) §7.6). Публичный адрес нужен комиссии: открыть сервис с настоящего телефона без установки Docker.

Площадка — Render, база — MongoDB Atlas. Решение о площадке — ADR-025 (вопрос 5) и ADR-027 в [09-decisions.md](./09-decisions.md); уточнение топологии веб-сервиса — дополнение ADR-027 в том же файле.

## 16.1. Что получится в конце

Два адреса вида `https://….onrender.com` (точное имя выдаст Render, своё красивое доменное имя не нужно):

| Адрес                                     | Что открывает                                                      |
| ----------------------------------------- | ------------------------------------------------------------------ |
| `https://<web>.onrender.com/`             | Демонстрационное приложение на русском                             |
| `…/debug`                                 | Стенд отладки с произвольными сигналами                            |
| `…/admin`                                 | Модерация справочника — только с токеном, который вы сами зададите |
| `…/widget-example/`                       | Пример виджета на «странице заказчика»                             |
| `https://<api>.onrender.com/health/ready` | Готовность API: `{"status":"ok"}` и непустой справочник            |
| `https://<api>.onrender.com/api/docs`     | Swagger UI                                                         |

Браузер пользователя ходит только на адрес **веб**-сервиса. Запросы `/api/…` nginx внутри веб-контейнера пересылает на API. Это тот же приём, что локально на порту 8080.

## 16.2. Что понадобится заранее

- Аккаунт [GitHub](https://github.com). Репозиторий уже есть: `https://github.com/alivanov/eSimDetector`. Если Render не увидит репозиторий — он должен быть доступен тому GitHub-аккаунту, которым вы войдёте.
- Карта **не нужна** ни для бесплатного Render, ни для бесплатного Atlas. Если площадка всё же попросит карту — это не обязанность тарифа, можно отказаться и остаться на Free.
- На своём компьютере: Node.js 24+, pnpm, этот репозиторий уже склонирован. Docker для публикации не нужен — он нужен только для локальной проверки.
- 40–70 минут на первый раз. Большая часть — ожидание создания кластера Atlas и первой сборки образов на Render (каждая сборка 10–15 минут).

### Ограничения бесплатного Render, о которых лучше знать сразу

- Сервис **засыпает через 15 минут без запросов**. Первый запрос после сна будит его примерно минуту — страница может крутиться, это не поломка. Демо-приложение на главной (`https://esimdetector.onrender.com`) перед проверкой eSIM само опрашивает `/health/live` через прокси веб-сервиса и показывает «Сервис просыпается…». Ручной `curl` к API необязателен, но остаётся запасным путём: [https://esim-detector-api.onrender.com/health/live](https://esim-detector-api.onrender.com/health/live) → `{"status":"ok"}`. Тот же текст — в README и в [07-integration.md](./07-integration.md) §7.6а.
- На один аккаунт — 750 «бесплатных часов» в месяц. Спящий сервис часы не тратит. Для редких проверок и демо этого достаточно. Если оба сервиса держать постоянно включёнными все сутки — часов не хватит, Render их остановит до следующего месяца.
- Бесплатный экземпляр — 512 МБ памяти. Если API при старте упадёт с нехваткой памяти, в логах будет `OOM` / `Killed`: тогда у этого одного сервиса смените тип экземпляра на **Starter** (около 7 USD в месяц). Веб (nginx) на Free укладывается.
- Бесплатные Web Service **не принимают** запросы по внутренней сети Render. Поэтому веб ходит на API по обычному публичному `https://…onrender.com`, а не по внутреннему имени.

## 16.3. Защита от вредителей: нужна ли captcha

**Нет, для демонстрационного стенда captcha не нужна** и в этом этапе не подключается.

Что уже защищает сервис (ADR-025, вопрос 9; [07-integration.md](./07-integration.md) §7.8):

| Мера                    | Зачем                                                                                         |
| ----------------------- | --------------------------------------------------------------------------------------------- |
| `RATE_LIMIT_RPM`        | Не больше 120 запросов в минуту с одного источника; лишние получают `429 RATE_LIMITED`        |
| `CORS_ORIGINS`          | Браузер с чужого сайта не сможет дергать API, если вы укажете только адрес своего веб-сервиса |
| `ADMIN_TOKEN`           | Раздел `/admin` и все эндпоинты модерации закрыты; пустой токен закрывает раздел целиком      |
| Валидация входа         | Тело запроса разбирается схемой; лишние поля отбрасываются                                    |
| Нет персональных данных | Сервис не собирает ФИО, телефоны, cookie; в журнале — хеш сигналов, не сами сигналы           |

Captcha (Yandex SmartCaptcha, hCaptcha, Cloudflare Turnstile) потребовала бы отдельного ключа, правок фронтенда и бэкенда и мешала бы комиссии на телефоне. Для демо с малым числом пользователей цена не оправдана.

Когда имеет смысл вернуться к вопросу:

- посторонние запросы держат API постоянно проснувшимся и сжигают бесплатные часы — сначала снизьте `RATE_LIMIT_RPM` до `30`;
- спам в очереди модерации — очередь и так за токеном `/admin`, публично в неё пишет только штатный сценарий «не нашли устройство»;
- реальный продакшен с ключом заказчика — тогда смотреть Turnstile или ключ `API_KEYS`, не форму с картинками.

Не публикуйте значение `ADMIN_TOKEN` в репозитории, в чате и в скриншотах для комиссии. Комиссии достаточно адреса веб-сервиса; админку показывают с токеном вживую, не высылая его заранее.

## 16.4. Альтернативы Render

Render остаётся площадкой по ADR-025/ADR-027: бесплатный тариф, Docker, не нужен свой домен. Ниже — если в процессе регистрации что-то не подойдёт.

| Площадка                                                                          | Когда рассматривать                                          | Почему не первый выбор                                                    |
| --------------------------------------------------------------------------------- | ------------------------------------------------------------ | ------------------------------------------------------------------------- |
| **VPS + тот же `docker compose`** (Timeweb, Selectel, любой VPS за 300–500 ₽/мес) | Хотите «как на ноутбуке, только в интернете» и без засыпания | Это уже свой сервер: SSH, файрвол, сертификат. Для первого деплоя сложнее |
| **Railway**                                                                       | Интерфейс проще Render, Docker из репозитория                | После исчерпания стартового кредита — только платно                       |
| **Fly.io**                                                                        | Нужен Docker «ближе к железу»                                | Больше понятий (регионы, тома, `fly.toml`), выше порог входа              |
| **Koyeb**                                                                         | Похож на Render, тоже есть Free и Docker                     | Меньше готовых инструкций, те же холодные старты                          |
| **Yandex Cloud / Cloud.ru**                                                       | Нужен хостинг в РФ                                           | Почти всегда с картой и счётом, не «нажал и выложил»                      |

Менять площадку в этом этапе не нужно. Если Render не зарегистрируется или Free окажется недоступен — напишите, разберём Railway или один VPS с уже знакомым `docker compose up`.

## 16.5. Первый деплой (fresh deploy)

Делайте шаги **по порядку**. Пропуск наполнения справочника (шаг Б) даст «живой» сайт с пустой базой: интерфейс откроется, но автоопределение на iPhone будет широким списком вместо узкой группы.

### Шаг А. База — MongoDB Atlas

Render свою MongoDB не даёт, поэтому база живёт отдельно и бесплатно.

1. Откройте [https://www.mongodb.com/cloud/atlas/register](https://www.mongodb.com/cloud/atlas/register).
2. Зарегистрируйтесь (Google / GitHub / почта).
3. Если спросит цель — подойдёт _Build a new application_ / личный проект. Имя организации и проекта оставьте предложенными или напишите `esim-detector`.
4. Создание кластера:
   - выберите **бесплатный** тариф: _Free_, _M0_ или _Shared_ — формулировка на сайте меняется, нужен кластер **без цены**;
   - провайдер облака — любой (AWS удобнее всего);
   - регион — ближайший к Европе, например Frankfurt / `eu-central-1`. Не Россия: у Atlas её в списке обычно нет;
   - имя кластера — `esim-detector` (или оставьте `Cluster0`).
5. Нажмите _Create_. Кластер собирается 3–8 минут. Можно сразу переходить к пользователю и сети — они настраиваются параллельно.

**Пользователь базы**

6. _Database Access_ → _Add New Database User_.
7. Authentication: _Password_.
8. Имя: `esim`.
9. Пароль: нажмите _Autogenerate_ и **скопируйте в надёжное место** (менеджер паролей или локальный файл вне репозитория). Сбросить потом можно, увидеть исходный — нет.
10. Права: _Atlas admin_ или _Read and write to any database_. Для демо достаточно.
11. _Add User_.

**Сеть**

12. _Network Access_ → _Add IP Address_.
13. Выберите **Allow Access from Anywhere** — в поле появится `0.0.0.0/0`.
14. Подтвердите. Это нужно потому, что у Render нет постоянного исходящего IP: без «отовсюду» база будет отказывать сервису. Защита — сложный пароль пользователя, не список IP.

**Строка подключения**

15. _Database_ → у вашего кластера _Connect_ → _Drivers_.
16. Скопируйте строку вида:

    `mongodb+srv://esim:<password>@cluster0.xxxxx.mongodb.net/?retryWrites=true&w=majority`

17. Вставьте пароль вместо `<password>` (угловые скобки тоже уберите).
18. **Добавьте имя базы `esim` после `.net/`**:

    `mongodb+srv://esim:ВАШ_ПАРОЛЬ@cluster0.xxxxx.mongodb.net/esim?retryWrites=true&w=majority`

    Без `/esim` драйвер попадёт в базу `test`, а API будет читать пустую `esim`. Это самая частая ошибка первого деплоя.

19. Сохраните готовую строку у себя. В репозиторий и в чат её не кладите.

### Шаг Б. Наполнить справочник со своего компьютера

База пока пустая. Наполнение — те же две команды, что локально (ADR-015): они **не** встроены в старт API.

В корне репозитория:

```bash
pnpm install
export MONGODB_URI='mongodb+srv://esim:ВАШ_ПАРОЛЬ@cluster0.xxxxx.mongodb.net/esim?retryWrites=true&w=majority'
pnpm seed load
pnpm seed rebuild-signatures
```

Ожидание: `load` пишет устройства, `rebuild-signatures` строит коллекцию экранов для iPhone. Вторая команда обязательна: без неё владелец iPhone получит длинный список моделей вместо узкой группы ([07-integration.md](./07-integration.md) §7.6).

Если `load` ругается на сеть или DNS — проверьте, что в Atlas _Network Access_ есть `0.0.0.0/0`, пароль без опечатки и в URI нет незакодированных спецсимволов (`@`, `#`, `%` в пароле нужно экранировать; проще сгенерировать пароль из букв и цифр).

### Шаг В. Зарегистрироваться на Render

1. Откройте [https://dashboard.render.com/register](https://dashboard.render.com/register).
2. Нажмите **Sign up with GitHub** — так Render сразу сможет читать репозиторий, отдельно пароль GitHub ему не отдаётся.
3. Разрешите доступ GitHub к аккаунту. Если спросит «все репозитории или выбранные» — достаточно `eSimDetector`.
4. Создастся _workspace_ (рабочее пространство). Имя любое, план **Hobby** (бесплатный).

### Шаг Г. Сервис API

1. В панели Render: **New → Web Service**.
2. Выберите репозиторий `eSimDetector`. Если его нет в списке — _Configure account_ / _GitHub_ и выдайте доступ к репозиторию, затем обновите страницу.
3. Заполните форму **точно так**:

   | Поле               | Значение                                      |
   | ------------------ | --------------------------------------------- |
   | Name               | `esim-detector-api`                           |
   | Region             | **Frankfurt** (тот же регион, что у веб ниже) |
   | Branch             | `main`                                        |
   | Language / Runtime | **Docker**                                    |
   | Root Directory     | оставьте пустым (корень репозитория)          |
   | Dockerfile Path    | `apps/api/Dockerfile`                         |
   | Instance Type      | **Free**                                      |

4. Раскройте **Advanced** и добавьте переменные окружения (кнопка _Add Environment Variable_). Имена — как в `.env.example`, значения — ниже.

   | Переменная                         | Значение                                              |
   | ---------------------------------- | ----------------------------------------------------- |
   | `MONGODB_URI`                      | строка из шага А, уже с паролем и `/esim`             |
   | `NODE_ENV`                         | `production`                                          |
   | `CORS_ORIGINS`                     | пока `*` — замените на адрес веб-сервиса после шага Д |
   | `RATE_LIMIT_RPM`                   | `120`                                                 |
   | `ADMIN_TOKEN`                      | длинная случайная строка, см. ниже                    |
   | `ALLOW_DERIVED_CATALOG_ANSWERS`    | `true`                                                |
   | `ALLOW_UNVERIFIED_CATALOG_ANSWERS` | `false`                                               |
   | `LOG_LEVEL`                        | `info`                                                |
   | `RESOLUTION_LOG_TTL_DAYS`          | `30`                                                  |

   Переменную `PORT` **не задавайте**: Render сам подставит порт и пробросит на него трафик. API уже читает `PORT` из окружения.

   `ADMIN_TOKEN` получите на своём компьютере:

   ```bash
   openssl rand -hex 32
   ```

   Вставьте вывод как значение. Сохраните копию у себя: восстановить из Render можно (открыть переменную), но лучше не терять.

5. Health Check Path (если поле есть): `/health/live`.
6. Нажмите **Create Web Service**.
7. Откроется журнал сборки. Первая сборка Docker-образа монорепозитория занимает **10–20 минут**. Статус _Live_ — сервис поднялся. Статус _Failed_ — откройте _Logs_, типичные причины в §16.8.
8. Скопируйте публичный адрес сервиса (в шапке страницы, вида `https://esim-detector-api.onrender.com`).
9. Проверка в браузере или терминале:

   ```bash
   curl https://esim-detector-api.onrender.com/health/live
   curl https://esim-detector-api.onrender.com/health/ready
   curl https://esim-detector-api.onrender.com/api/v1/catalog/meta
   ```

   `live` сразу отвечает `{"status":"ok"}`. `ready` — `ok` и `catalog: ready`. `catalog/meta` — `deviceCount` больше нуля (порядка тысячи). Если `deviceCount` равен 0 — шаг Б не дошёл до этой базы: проверьте, что `MONGODB_URI` у команды `seed` и у сервиса **буквально совпадают**, включая `/esim`.

   Если API только что уснул, первый `curl` может идти до минуты — это нормально для Free.

### Шаг Д. Сервис веб-приложения

1. **New → Web Service** ещё раз (не Static Site: объяснение в дополнении ADR-027).
2. Тот же репозиторий `eSimDetector`.
3. Форма:

   | Поле               | Значение                          |
   | ------------------ | --------------------------------- |
   | Name               | `esim-detector-web`               |
   | Region             | **Frankfurt** — тот же, что у API |
   | Branch             | `main`                            |
   | Language / Runtime | **Docker**                        |
   | Dockerfile Path    | `apps/web/Dockerfile`             |
   | Instance Type      | **Free**                          |

4. Переменные:

   | Переменная     | Значение                                                                           |
   | -------------- | ---------------------------------------------------------------------------------- |
   | `API_UPSTREAM` | публичный адрес API **целиком**, например `https://esim-detector-api.onrender.com` |
   | `PORT`         | `8080`                                                                             |

   `API_UPSTREAM` — со схемой `https://`, без слэша в конце, без `/api`. nginx подставит его в прокси и при HTTPS отправит имя хоста в TLS (SNI): иначе Render/Cloudflare обрывают рукопожатие, в логах веба `SSL alert number 40`, в браузере 502. `PORT=8080` нужен потому, что nginx в образе слушает 8080, а Render по умолчанию ждёт 10000.

5. Health Check Path: `/`.
6. **Create Web Service**. Сборка снова 10–20 минут.
7. Скопируйте адрес вида `https://esim-detector-web.onrender.com`.

### Шаг Е. Закрыть CORS и перезапустить API

Пока `CORS_ORIGINS=*` — браузер с любого сайта может вызвать API. Для сдачи ограничение должно быть содержательным (ADR-025, ADR-027).

1. Откройте сервис `esim-detector-api` → _Environment_.
2. Замените `CORS_ORIGINS` на адрес веб-сервиса без слэша в конце: `https://esim-detector-web.onrender.com`.
3. Сохраните. Render сам перезапустит API (минута-две).

Демонстрационное приложение ходит на API через свой же адрес (прокси nginx), поэтому CORS для главной страницы не участвует. Значение нужно странице `/widget-example/` только если когда-нибудь укажете внешний `data-api-base`, и любым прямым вызовам API из браузера на другом домене.

### Шаг Ж. Проверить как пользователь

Сначала разбудите API (если он успел уснуть): откройте `https://<api>.onrender.com/health/ready` и дождитесь ответа. Затем на телефоне или в браузере компьютера:

| Проверка                                         | Ожидание                                                                 |
| ------------------------------------------------ | ------------------------------------------------------------------------ |
| `https://<web>.onrender.com/`                    | Экран проверки, автоопределение либо уточнение на русском                |
| `https://<web>.onrender.com/debug`               | Поле сигналов и полный ответ сервиса                                     |
| `https://<web>.onrender.com/admin`               | Форма ввода токена; после ввода `ADMIN_TOKEN` — очередь модерации        |
| `https://<web>.onrender.com/widget-example/`     | Виджет на «чужой» странице с красным текстом снаружи и нормальным внутри |
| `https://<api>.onrender.com/api/docs`            | Swagger                                                                  |
| `https://<api>.onrender.com/api/v1/catalog/meta` | `deviceCount` > 0                                                        |

Адреса этой выкладки уже вписаны в [07-integration.md](./07-integration.md) §7.6а и в раздел «Публичный стенд» корневого README: веб — `https://esimdetector.onrender.com`, API — `https://esim-detector-api.onrender.com`.

## 16.6. Обновление уже выложенного стенда

Render сам пересобирает сервис при `git push` в ветку `main`, если при создании сервиса не выключали _Auto-Deploy_ (по умолчанию включено). Отдельная «кнопка выкладки» после каждого коммита не нужна.

Вход в панель Render через GitHub (OAuth) **не** включает автодеплой. Нужно отдельно установить GitHub App: [github.com/apps/render](https://github.com/apps/render) → _Install_ → доступ к репозиторию `eSimDetector`. Пока в GitHub → Settings → Applications → _Installed GitHub Apps_ нет карточки Render, пуш до Render не доходит; тогда **Manual Deploy → Deploy latest commit**.

### Изменился только код (API, веб, виджет)

1. Проверьте локально: `pnpm test`, при правках интерфейса — `docker compose up -d` и сценарий руками.
2. Закоммитьте и отправьте в `main`:

   ```bash
   git push origin main
   ```

3. В панели Render у каждого сервиса появится событие _Deploy_. Дождитесь _Live_ у **обоих** (`esim-detector-api` и `esim-detector-web`). Сборка снова 10–15 минут на сервис.
4. Если Auto-Deploy выключен: у сервиса кнопка **Manual Deploy → Deploy latest commit**.

Переменные окружения и база при таком обновлении не трогаются. Справочник в Atlas остаётся как был.

### Изменились данные справочника в репозитории (`data/catalog/`)

Код на сервере сам файлы в MongoDB не загружает (ADR-015). После пуша, который содержит новые данные:

```bash
export MONGODB_URI='mongodb+srv://esim:ВАШ_ПАРОЛЬ@cluster0.xxxxx.mongodb.net/esim?retryWrites=true&w=majority'
pnpm seed load
pnpm seed rebuild-signatures
```

Затем перечитайте кэш API одним из способов:

- в панели Render у `esim-detector-api` нажмите **Manual Deploy → Restart**, либо
- если задан `ADMIN_TOKEN`: `POST https://<api>.onrender.com/api/v1/admin/catalog/reload` с заголовком `X-Admin-Token`.

Без перезапуска или `reload` API продолжит отвечать по старому снимку в памяти ([07-integration.md](./07-integration.md) §7.6, третий шаг). Точечное решение в `/admin` (привязать код, изменить статус) применяется сразу и этого шага не требует.

### Изменилась переменная окружения

Сервис → _Environment_ → поправить значение → сохранить. Render перезапустит только этот сервис. Если поменяли адрес API — не забудьте `API_UPSTREAM` у веб-сервиса.

### Откатить неудачную выкладку

У сервиса _Rollback_ (на Free доступны два последних деплоя). База Atlas при откате кода **не** откатывается: если вы уже прогнали `pnpm seed load` с новыми данными, решайте отдельно, нужны ли они со старым кодом.

## 16.7. Повторный деплой «с нуля»

Если сервисы удалили или нужен чистый стенд на другом аккаунте — повторите шаги А–Ж. Что можно переиспользовать:

- кластер Atlas и наполненную базу — не удаляйте их без нужды, достаточно новой строки `MONGODB_URI` в новом API;
- `ADMIN_TOKEN` — можно оставить тот же, если он не засветился.

Что нельзя переиспользовать: имена `onrender.com`, если старые сервисы ещё существуют (Render добавит суффикс). Старые сервисы перед повторным созданием с тем же именем удалите: сервис → _Settings_ → _Delete Web Service_.

## 16.9. Что сознательно не делается в этом этапе

- Свой домен и DNS — не нужны, адреса `onrender.com` достаточны для комиссии.
- Файл `render.yaml` (Blueprint) — не заводится: первый деплой делается руками в панели, чтобы было понятно, какой сервис за что отвечает.
- Captcha и Cloudflare перед стендом — см. §16.3.
- Деплой из этой инструкции агентом — не выполняется: выкладку делает владелец аккаунтов Atlas и Render.
