# eSIM Detector — правила проекта

Сервис определения устройства пользователя и статуса поддержки eSIM. Реализуется цепочкой агентов, каждый из которых начинает без контекста предыдущего. Единственная общая память между агентами — документация в `docs/`, поэтому её актуальность критична.

## Перед началом работы

1. Прочитай `docs/README.md`, затем документ по своей задаче из таблицы навигации.
2. Прочитай `docs/09-decisions.md`. Решения ADR обязательны к соблюдению. Не согласен — опиши проблему в отчёте, но не меняй решение молча.
3. Проверь `docs/12-open-questions.md`: часть вопросов ждёт ответа пользователя, и трогать их самостоятельно не нужно.

## Язык и стек

- Весь код — TypeScript. Файлов `.js` в проекте нет, включая конфигурационные скрипты и тесты.
- NestJS, Mongoose, MongoDB на бэкенде; React и Vite на фронтенде (ADR-011).
- Весь текст, видимый пользователю, — только на русском языке.
- Документация и сообщения коммитов — на русском языке.
- Версии зависимостей вручную не пиши: устанавливай пакеты менеджером пакетов, чтобы получить актуальные.

## Строгая типизация на границах системы

Внешние данные — сигналы браузера, пользовательский ввод, строки CSV, переменные окружения — не приводятся к типу утверждением `as` и не помечаются `any`. Они проходят валидацию схемой и только после этого получают тип предметной области (ADR-016).

```ts
// ❌ создаёт видимость типобезопасности при её отсутствии
const row = parsedCsvRow as DeviceRow;

// ✅ тип появляется после проверки данных
const row = parseDeviceRow(parsedCsvRow); // возвращает DeviceRow либо ошибку валидации
```

## Предметные правила, нарушение которых стоит баллов

Критерий К1 весит 0,40 и дополнительно разрешает ничью при равенстве итоговых баллов. Поэтому ложный ответ дороже отсутствия ответа.

1. **Неизвестное устройство никогда не получает догадку** — только статус `clarification_required`. Эвристика «модель новая, значит eSIM есть» запрещена.
2. **Цифры поколения и модификаторы линейки сравниваются точно.** Нечёткое сравнение применяется только к названиям бренда и семейства. Иначе `iPhone 12` и `iPhone 13`, отличающиеся на одну правку, начнут путаться между собой.
3. **На iOS определяется группа моделей, а не модель.** Ответ выдаётся, когда статус eSIM совпадает у всех кандидатов, с флагом `exactModelKnown: false`. Точную модель iPhone из браузера получить невозможно, попытки её «доопределить» порождают ложные результаты.
4. **Сервисные коды моделей из CSV-выгрузки языковой модели недостоверны.** Валидируй по вендорским шаблонам, коллизии отправляй в карантин.
5. **Результат «не удалось определить» — это код 200 со статусом**, а не ошибка HTTP.

## Тесты

- Модульные тесты обязательны, e2e — по необходимости.
- Тесты никогда не обращаются к базе данных приложения. Только через `withTestDatabase()` из `packages/test-utils` (ADR-017).
- Тесты обязаны проходить из чистого клона без Docker, без запущенной MongoDB и без файла переменных окружения.

## Комментарии в коде

Комментируй только неочевидные ограничения, которые нельзя выразить самим кодом. Не описывай в комментариях внесённые изменения и не пересказывай то, что делает соседняя строка.

## Документация

Отклонился от описанного в документации — обнови соответствующий документ в `docs/`. Расхождение кода и документации снижает оценку по критерию К3 с весом 0,20.

## Завершение работы

- Не коммить без явной просьбы пользователя.
- Заверши работу отчётом и промптом для следующего агента по навыку `agent-handoff`.

## Правила по областям кода

В `.cursor/rules/` лежат правила, подключаемые по путям: чистота переиспользуемых пакетов, изоляция тестовой базы, границы API, данные справочника, фронтенд и виджет.
